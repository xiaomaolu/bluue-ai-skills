网页设计方法论：给 Agent 的执行规范
2026年10月5日 · @blyue
如何使用本文档
这是一份给 AI agent 的网页设计执行规范：先按「设计流程」做决定，再按各章规则落地，最后用「自检清单」验收。适用于网站、落地页、应用界面和仪表盘。
优先级（冲突时上面的赢）：
1. 用户的明确要求
2. 已有的品牌规范或设计系统
3. 本文档的规则
4. 你自己的默认习惯
怎么读数值：文中的数字是默认值。有具体理由可以改，没有理由就照用。改了要能说出为什么。
十条核心原则（记不住全文时，至少守住这些）：
1. 先定目的，再定样式。 说不出「这个页面要让谁做什么」，就不要开始画。
2. 每屏只有一个主角。 其他元素都为它让路。
3. 内容先行。 用真实文案和真实数据设计，不用占位文字。
4. 先定调性。 用三个形容词写下页面气质，之后所有选择都服从它。
5. 排印优先于装饰。 字号、字重、行高调对了，页面已成立八成。
6. 数值只取自刻度。 间距、字号、圆角、颜色都从预设集合里选，不随手写。
7. 用色克制。 强调色只给需要被点击或被注意的东西。
8. 对比要么明显，要么没有。 两个元素相差不到约 1.25 倍，看起来像失误而不是设计。
9. 每个决定都有理由。 答不出理由的元素，删掉。
10. 避开默认感。 做一个具体的、有立场的选择，而不是最安全的那个。
设计流程（思路）
按下面七步走，前四步不写任何样式。难看的页面多半不是配色差，而是前四步被跳过了。
1. 弄清目的。 回答四个问题：谁在看？他带着什么问题来？看完要做的那一件事是什么？他在什么设备、什么情境下看？信息不足且猜错代价大时先问用户；否则写下假设，继续做。
2. 盘点内容。 列出所有要出现的内容，按重要性编号排序。排在后三分之一的，删掉或移到次级页面。此时就写真实文案（见「文案」）。
3. 定调性。 写下三个形容词和一个「不是什么」。例：「沉稳、精确、有温度；不是冷冰冰的企业风」。再用下面的对照表把调性翻译成视觉决定。
4. 定结构。 先用纯文字列出区块顺序，每个区块写一句「它的任务是什么」。一个区块只做一件事。标出每屏的主角。
5. 建系统。 先定字号阶梯、间距刻度、色板、圆角、阴影这几组变量，再画页面（见「规范与 Design Tokens」）。
6. 实现。 从手机宽度开始。顺序是：排版和间距 → 颜色 → 装饰和动画。先用灰阶把层级做成立，再上色。
7. 审查与删减。 把页面渲染出来实际看一遍。做眯眼测试，逐个元素问「删掉会损失什么」，然后走一遍「自检清单」。

审美逻辑
好的页面由三样东西构成：清晰的层级、一致的系统、一处有性格的选择。判断任何视觉决定时，用下面八条标准。
1. 层级。 读者要在 3 秒内知道：这是什么、哪个最重要、下一步点哪里。层级最多三级：主、次、辅。区分层级的工具按强度排序是：尺寸 > 字重 > 颜色对比 > 位置 > 留白 > 装饰。每次用一到两个就够，不要全上。
2. 统一与对比。 一致带来信任，对比带来重点。功能相同的东西长得一样；功能不同的东西明显不同。
3. 克制。 想突出一个元素，先削弱它周围的元素，而不是把它再加粗。全都强调等于没有强调。
4. 理由。 每个元素要么帮助理解和操作，要么传达调性。两样都不沾的，删掉。
5. 具体。 形式要贴合内容的性格。律所和玩具店不该共用一副骨架。
6. 签名时刻。 每个页面选一处，且只选一处，投入超额的心思：一个超大的标题排版、一个出人意料的布局，或一个精致的交互。其余部分保持安静。
7. 张力。 大与小、密与疏、粗与细、规整与破格。没有张力的页面是平的。先建立规则，再有意打破一次。
8. 诚实。 不放假评价、假数据、没有信息的装饰图表。留白是主动的设计元素，不是待填的空位。
质感来自读者说不出但感觉得到的细节：一致的圆角、精确的间距、调过的字间距、光学对齐。这些细节不出彩，但缺了就显得廉价。
五个快速测试：
• 眯眼测试：眯着眼看页面，还能分出主次吗？分不出，说明层级不够。
• 灰阶测试：去掉颜色，层级还成立吗？不成立，说明你在靠颜色硬撑。
• 删除测试：逐个遮住元素。遮住后没有损失的，删掉。
• 换牌测试：把 logo 换成竞品的，页面依然合适吗？合适，说明设计太通用。
• 五秒测试：只看五秒，能复述页面是做什么的、要我做什么吗？
布局
布局的任务是安排阅读顺序：让眼睛先落在主角上，再沿一条明确的路径走到行动点。
网格
• 桌面 12 列，平板 8 列，手机 4 列。列间距桌面 24px，手机 16px。
• 内容区最大宽度 1200–1280px。纯阅读内容限宽 640–720px：中文每行 25–40 字，英文每行 45–75 个字符。
• 页面左右边距：手机 16–20px，平板 32px，桌面至少 48px。
• 所有元素的左右边缘都落在列线上。
页面结构
• 一个区块一个任务。区块之间的垂直间距：桌面 96–128px，手机 48–64px。
• 首屏说清三件事：这是什么、给谁用、现在做什么。首屏不必塞满；露出下一区块的一点边缘，暗示可以往下滚。
• 落地页的起点顺序：首屏主张 → 信任证明 → 核心价值（不超过三点）→ 具体展示 → 打消疑虑 → 再次给出行动点。这是起点，不是模板，按内容删改。
• 相邻区块要有节奏变化：交替改变密度、对齐方式或背景。不要连续出现三个结构相同的区块。
视觉动线
• 文字密集的页面，读者按 F 形扫视；内容稀疏的营销页，按 Z 形扫视。
• 最重要的内容放在左上起点和动线的拐点，主行动点放在动线终点。
• 用尺寸、留白和指向性元素（人物视线、线条、箭头）引导眼睛。
对称与分栏
• 居中对称显得庄重稳定，适合短文案和单一焦点，但用多了就平庸。
• 不对称更有活力。分栏优先用 5/7 或 4/8 列，制造主次；只有两侧内容真正对等时才用 6/6。
• 同一组图片统一比例，只从 1:1、4:3、3:2、16:9 里选。
深度
• 层次最多三层：页面底、表面（卡片）、浮层（弹窗、菜单）。
• 表达层次优先用背景色差和边框，其次才是阴影。
响应式
• 移动优先。断点：640、768、1024、1280px。
• 小屏不是缩小，而是重排：多栏变单栏，次要内容折叠或后移，导航收进菜单。
• 触控目标至少 44×44px，相邻目标间隔至少 8px。
• 手机正文不小于 16px；输入框字号小于 16px 会让 iOS 自动放大页面。
• 不允许页面横向滚动。有意的横向列表要露出下一项的边缘。
• 大标题用 clamp() 随视口流式缩放，例如 clamp(2.25rem, 5vw, 3.75rem)。
密度
• 营销页宽松，工具页紧凑。同一页面内密度保持一致。
字体与排版
排印决定页面八成的观感。顺序是：选对字体，定一套字号阶梯，再调行高和字距。
选字
• 最多两个字族：一个用于标题，一个用于正文。需要时加一个等宽字体给代码和数据。
• 配对只有两种安全做法：同一字族的不同字重，或差异明显的两种（衬线标题配无衬线正文）。不要配两个相似的无衬线。
• 正文字体选字重齐全、小字号下清晰的。标题字体可以有性格。
• 不要无理由地默认用 Inter、Roboto、Arial。调性是「中性工具」时它们合适；其他调性要选更贴切的字体。
• 字重只用两到三个：正文 400，强调 500–600，标题 600–700。小字号不用 300 及以下。

规律：字越大，行高越小、字距越紧；小号全大写文字要加宽字距。
段落
• 正文左对齐。居中只用于不超过三行的短文案。不用两端对齐。
• 段间距为正文行高的 0.75–1 倍。
• 标题上方的间距是下方的两倍左右，让标题贴近它所属的内容。
• 标题用 text-wrap: balance，正文用 text-wrap: pretty，避免末行只剩一两个字。
• 强调用加粗或颜色。下划线留给链接。不用全大写写长句。
• 文字颜色分三级：主文字、次要文字、弱化文字。次要信息优先降颜色，而不是缩字号。
• 表格和数据里的数字用等宽数字：font-variant-numeric: tabular-nums。
中文排版
• 正文行高 1.7–1.8，比英文更大。每行 25–40 字。
• 中文与英文、数字之间留一个空格，或使用 text-autospace。
• 使用全角标点。引号用「」或“”，全站统一。
• 中文不用斜体，强调用加粗或着重色。
• 中文一般不调字距；大标题可加 0.02–0.05em 让它更舒展。
• 中文网页字体文件大。优先用系统字体栈，或只为标题加载子集化的字体。
• 字体栈里英文字体写在前面，例如："Inter", "PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif。
颜色
颜色用来指路和表达情绪，不用来装饰。默认配置是：一套带色相的中性色、一个主色、一个可选的强调色、四个语义色。
构建色板的顺序
1. 中性色。 做 9–11 级灰阶（50 到 950）。给灰色加一点主色的色相，饱和度 2–8%，不用纯灰。暖调页面用暖灰，冷调页面用冷灰。
2. 主色。 只选一个，生成 50–900 的色阶。500–600 用于按钮和链接，50–100 用于浅色底，700 用于悬停和按下。
3. 强调色（可选）。 与主色对比明确，用量极少。
4. 语义色。 成功用绿，警告用琥珀，错误用红，信息用蓝。只用于对应语义，不拿来装饰。
用 OKLCH 或 HSL 定义颜色，让同一色阶里色相稳定、明度均匀递进。
比例
按 60 / 30 / 10 分配：60% 是背景中性色，30% 是表面和文字，10% 以内是主色和强调色。实际页面里，强调色常常不到 5%。
用法规则
• 主色只给：主按钮、链接、选中状态、关键数据。每屏最多一个实心主色按钮。
• 大面积主色背景只能出现在签名时刻那一处。
• 文字不用纯黑 #000，用带色相的近黑（中性 900）。大背景可用近白（中性 50），再把纯白表面放在上面形成层次。
• 文字三级：主文字用中性 900，次要文字用中性 600，弱化文字用中性 500。
• 边框用中性 200，分隔线比边框再浅一档。
• 渐变只在相邻色相之间做（色相差不超过 30°），或只变明度。不做紫到蓝到粉的多色渐变。
• 彩色背景上的文字，用同色相的深色或浅色，不用灰色；灰字压在彩色底上会显脏。
• 不只靠颜色传达信息。状态要同时有图标或文字，照顾色觉障碍的读者。
• 注意地区语义：中国大陆的金融数据红涨绿跌，欧美相反。

深色模式
• 不是把颜色反过来。背景用带色相的深灰，不用纯黑；文字用浅灰（约 #EDEDED），不用纯白。
• 层级越高的表面越亮。深色下阴影几乎看不见，改用亮度差和边框表达层次。
• 主色降低饱和度、提高明度，通常改用 400 档。
• 边框用白色 8–12% 不透明度。
• 两种模式都要单独检查对比度。
间距与对齐
间距表达关系：越近越相关。对齐表达秩序：页面上隐形的对齐线越少，越显整洁。

以 4px 为基数，只从这组值里选：4、8、12、16、24、32、48、64、96、128。

亲密性
• 组内间距小于组间间距，至少差一倍：8 对 16，16 对 32。
• 容器内元素之间的间距，要小于容器的内边距。
• 标题离它下方的内容近，离上方的内容远。
• 分组工具按优先级使用：间距 > 背景色差 > 分隔线 > 边框盒子。能用前一种解决，就不用后一种。
留白
• 留白与重要性成正比：越重要的东西，周围越空。
• 觉得「好像有点太空」的时候，通常刚好。
• 同一层级的区块使用相同间距，形成稳定的垂直节奏。
• 不要把内容均匀铺满。密集和空旷要成对出现，才有节奏。
对齐
• 默认左对齐。一个页面的主要垂直对齐线控制在一到两条。
• 同一区块内不混用对齐方式。长段正文配居中标题是常见错误；正文左对齐，标题也左对齐。
• 居中只给短内容和单一焦点：首屏主张、空状态、确认弹窗。
• 表格里文字左对齐，数字右对齐，表头跟随所在列。
• 同一行里不同字号的文字按基线对齐，不按盒子的顶边或中心。
• 图标与文字垂直居中，图标尺寸约等于文字行高：16px 文字配 16–20px 图标。
• 同一行的卡片等高，卡片内的按钮底部对齐。
• 表单标签放在输入框上方并左对齐；输入框宽度反映预期的输入长度。
光学对齐（数学居中不等于看起来居中）
• 圆形里的播放三角形要向右移一点，才显得居中。
• 圆形和尖角图形要比方形略大，才显得一样大。
• 大标题的左边缘要向左拉 1–3px，才与下方正文看起来对齐。
• 带图标的按钮，图标一侧的内边距比文字一侧少 2–4px。
• 判断标准只有一个：渲染出来看，眼睛觉得齐才算齐。
组件
组件只有两条主线：同类组件全站长得一样；每个可交互的组件，把所有状态都设计完。
通用规则
• 状态。 可交互组件必须有：默认、悬停、键盘聚焦、按下、禁用、加载。承载数据的组件另加：空、错误、成功。
• 焦点环。 2px 粗，偏移 2px，与背景对比至少 3:1，用 :focus-visible 触发。不能去掉焦点样式而不给替代。
• 高度。 三档：32px（紧凑）、40px（默认）、48px（大号或触控）。同一行的按钮和输入框等高。
• 圆角。 全站一种圆角语言：小元素一档，大容器一档。嵌套时，内圆角 = 外圆角 − 两者间距。
• 阴影。 只有一个光源，从上方来。柔和、不透明度 5–15%、带一点背景色相。层级越高，阴影越大越淡。
• 边框与阴影。 区分表面时，从边框、阴影、背景色差里选一种为主，不叠加三种。
• 图标。 只用一套图标库，统一线宽（1.5 或 2px）和尺寸（16、20、24px）。不用 emoji 充当图标。只有图标的按钮要有文字提示和无障碍标签。
按钮
• 三个级别：主按钮（实心主色）、次按钮（描边或浅色底）、文字按钮。一个视图只有一个主按钮。
• 危险操作用红色，且不设为默认聚焦项。
• 水平内边距约为垂直的两倍。最小宽度约 80px。
• 加载时保持原宽度、显示加载指示、禁止重复点击。
• 跳转用链接，执行操作用按钮，不混用。
• 主按钮在按钮组里的位置全站一致。
表单
• 标签始终可见，放在输入框上方。不用占位符代替标签；占位符只展示格式示例。
• 单列布局。只有关系紧密的短字段才并排，如城市和邮编。
• 必填和选填，只标记数量少的那一类。
• 离开字段时再校验，不在输入中途报错。错误信息放在字段下方，说清怎么改，同时用红色边框、图标和文字。
• 设对输入类型和自动填充属性，让手机弹出正确的键盘。
• 选项不超过 5 个用单选按钮，更多用下拉。立即生效的设置用开关，需要提交的用复选框。
• 提交后给出明确反馈：成功提示、跳转，或指出错误位置。
卡片
• 内容是独立、并列的单元时才用卡片。不要把所有东西都装进卡片。
• 不做卡片套卡片。
• 内部顺序：图 → 标题 → 描述 → 元信息或操作。
• 整张卡片可点击时：整卡有悬停状态，内部只有一个主要去向。
导航
• 顶级项目不超过 7 个，5 个最好。当前所在位置要有明确标识。
• 常规排布：标志在左，主导航居左或居中，主行动点在右。
• 手机端：应用用底部标签栏（不超过 5 项），网站用折叠菜单。
• 吸顶导航高度 56–72px。
弹窗与提示
• 弹窗只用于必须立即决定或需要专注的任务。能在页面内解决的，不用弹窗。不做弹窗套弹窗。
• 确认类弹窗宽 400–560px，表单类不超过 720px。遮罩用黑色 40–60% 不透明度。
• 支持 Esc 关闭；焦点锁定在弹窗内；关闭后焦点回到触发它的元素。
• 轻提示 3–5 秒后自动消失，只用于非关键信息。关键错误留在页面上。
表格
• 行高 40–56px。去掉竖线，横向用细线或斑马纹，二选一。
• 表头用小号、次要色文字。长表格表头吸顶。
• 文字左对齐，数字右对齐并用等宽数字。
图片
• 用固定宽高比的容器加 object-fit: cover，避免加载时布局跳动。写替代文本。
• 全站图片风格统一：同一色调，或同一种插画风格。
• 没有好图时，用排版、色块或真实产品截图代替，不用空泛的素材图。
• 图上压字，要加遮罩或渐变保证对比度。
加载、空、错误
• 等待不到 1 秒不显示加载；1–3 秒用加载指示或骨架屏；更久要给进度和说明。
• 骨架屏的形状要匹配最终内容。
• 空状态说明为什么是空的，并给出下一步操作。
• 错误状态说明发生了什么、用户能做什么。
文案
文案是设计的一部分，而且要先写。读者只扫读不细读，所以每一处文字都要短、具体、说人话。
总则
• 先写文案，再做布局。文案变了，布局跟着变。
• 具体胜过形容。用数字、名词和结果，不用形容词。
• 说用户得到什么，不说产品有什么。
• 一句话只说一个意思。删掉空词：极致、赋能、一站式、引领、无缝、革命性、高效便捷。
• 用用户的词，不用内部术语。同一个东西全站只用一个叫法。
• 语气像一个懂行的朋友当面说话。称呼用「你」还是「您」，全站统一。
• 读出声来检查。读着别扭的，改。
标题
• 首屏主标题说清产品是什么，或用户能得到什么。中文不超过约 14 个字，英文不超过约 8 个词。
• 副标题用一到两句补充「怎么做到」或「给谁用」。
• 区块标题写结论，不写类别。
• 把页面所有标题连起来读，应该能讲完整个故事。
按钮与链接
• 动词开头，说出点击后的结果。中文 2–6 个字。
• 按钮文案与它打开的下一步页面标题一致。
• 打消顾虑的小字放在按钮旁边，如「无需绑定银行卡」「随时取消」。
• 成对按钮用具体动词，不用「是 / 否」。
• 链接文字描述去向，不写「点击这里」。
微文案
• 错误信息：说发生了什么、怎么解决。不责怪用户，不露技术代码。
• 空状态：说这里将来会出现什么、怎么开始。
• 确认弹窗：标题写具体动作，正文写后果，按钮重复那个动词。
• 成功提示：简短确认，必要时给下一步。
• 占位符：给一个格式示例，如 name@example.com。

格式
• 标题不加句号，按钮不加标点。感叹号每页最多一个。
• 数量用阿拉伯数字。列表各项保持相同句式。
• 营销页正文每段不超过三句。
• 不用占位假文。不知道真实内容时，写一个可信的示例并标明是示例。
• 不编造用户评价、客户标志和数据。需要时留出标明「待填写」的位置。
动画
动画只做三件事：给反馈、解释变化、引导注意。三件都不沾的动画，删掉。
原则
• 反馈：让用户知道「我点到了」。连续：让用户看到东西从哪来、到哪去。引导：把视线带到该看的地方。
• 界面动画宁快勿慢。用户每天要看上百次的动效，应该快到几乎察觉不到。
• 一个精心编排的进场，胜过散落各处的小动效。
• 高频操作不加动画：打字、快捷键触发的动作、连续点击。
时长

动什么
• 只动 transform 和 opacity。不动宽高、边距和定位属性，它们会触发重排，导致卡顿。
• 位移要小：进场移动 8–24px 就够。缩放从 0.95 到 1。不要从屏幕外飞进来。
• 最稳妥的组合：淡入加轻微上移。
编排
• 进场顺序跟随阅读顺序：标题 → 副标题 → 按钮 → 图片。整段编排控制在 1 秒左右。
• 同一时刻只有一个东西在吸引注意。
• 滚动触发的进场，每个元素只播一次，且不能让读者等动画播完才能读内容。
• 不劫持滚动：不改滚动速度，不改滚动方向。
• 长列表只让前 6–8 项错开进场，其余一起出现。
交互反馈
• 悬停：从变色、变背景、加阴影、上移 1–2px 里选一种，全站同类元素用同一种。
• 按下：缩小到 0.97–0.98，或颜色加深一档。
• 列表增删和排序要有过渡，让用户看到东西去了哪里。
• 骨架屏用柔和的明暗脉动，周期 1.5–2 秒。
无障碍与性能
• 用户开启了「减少动态效果」（prefers-reduced-motion）时，去掉位移、缩放和视差，只保留淡入淡出或直接切换。
• 不做每秒闪烁超过 3 次的效果。自动循环的动画要能暂停。
• 目标 60 帧。在中低端手机上测试。不同时给大量元素加动画。
• 视差和鼠标跟随效果默认不用，除非它就是那一处签名时刻。

变量的使用规则
• 分两层：原始值（--neutral-600）和语义变量（--text-secondary）。组件里只引用语义变量，这样换主题只改一处。
• 需要一个刻度里没有的值时，先问是不是设计出了问题。确实需要，就把它加进刻度，而不是在组件里写死。
• 断点固定为 640、768、1024、1280px。
代码与结构
• 用语义化标签：header、nav、main、section、footer。每页一个 h1，标题层级不跳级。
• 执行操作用 button，跳转用 a。不用 div 模拟可点击元素。
• 页面设置正确的 lang 属性；中文页面用 zh-CN。
• 字体最多加载两个字族、四个文件，并设置 font-display: swap。
• 图片写明宽高、懒加载，优先用 WebP 或 AVIF。
• 首屏内容不能依赖脚本动画才显示。
无障碍底线（不可协商）
• 所有操作都能只用键盘完成，焦点始终可见。
• 对比度达到「颜色」一章的标准。
• 触控目标至少 44×44px。
• 每个输入框都有关联的标签；每张有信息的图片都有替代文本。
• 不只靠颜色传达状态。
交付时附带的说明
• 调性的三个形容词。
• 你做了哪些假设。
• 哪里偏离了本规范，以及理由。

目的与结构
[ ] 能用一句话说出：这个页面让谁做什么
[ ] 五秒内能看出页面是做什么的、下一步点哪里
[ ] 每屏只有一个主角，每个区块只做一件事
[ ] 眯眼看，主次依然分明
[ ] 有且只有一处签名时刻
排版
[ ] 字族不超过两个，字号不超过六个，全部来自阶梯
[ ] 标题与正文至少相差两档
[ ] 正文行宽在限定范围内，行高符合中英文各自的标准
[ ] 没有多行居中的正文，标题末行没有孤字
颜色
[ ] 去掉颜色后，层级仍然成立
[ ] 主色只出现在按钮、链接、选中状态和关键数据上
[ ] 所有文字对比度达标，深色模式单独检查过
[ ] 没有只靠颜色表达的状态

[ ] 所有间距来自刻度
