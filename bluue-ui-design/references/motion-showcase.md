# 静态设计转展示动画：按需使用

只在用户要求动画演示、产品展示视频或 GIF 时使用。普通悬停、菜单、弹窗和异步反馈遵循主文件中的产品交互规则。

## 先保留设计，再写动作

- 如果输入是明确的 Figma 画面、截图或已实现页面，先核对最终静态画面的构图、文本、素材、字体、裁切、层级和背景。动画需求本身不授权重设计。
- 参考中的照片、纹理、背景与固定表面维持原意；不要为了方便录制换成纯色，或给背景增加未请求的平移和缩放。
- 每个需要运动的区域先写一句故事：用户做了什么、对象怎样变化、看到了什么结果。例如“选择一条记录，右侧出现该记录的详情”。只在有信息价值的区域动，不要求每张卡片都动。
- 产品页面保持真实 HTML 文本、操作语义与项目组件。独立视频可按精确还原需要使用导出图层；不把只可观看的合成画面当成已实现产品 UI。
- 素材不可用时说明缺失，使用明确标记的示意或待补方案，不伪造真实产品截图或未实现能力。

## 自然的展示节奏

- 阅读顺序引导动作，重要动作之间留出观察结果的时间；重点区域错开，不全屏同时表演。
- 空态到结果只在演示内容确实需要这一过程时使用，不强制所有作品从空白或模糊开始。
- 静态说明文字一般不循环。数字、图表、提示和结果来自同一状态模型，不用无意义计数、游标或光效冒充真实变化。
- 展示动画可比产品即时反馈慢，但不为了“柔和”让动作不可辨认或长时间等待。默认不添加镜头运动、弹跳、光晕或模糊，除非内容与用户目标需要。
- 循环应连贯：重置前后图层、裁切、文本和数据都一致；非循环演示保持完成结果，不反复清空用户上下文。
- 网页中的动画按视口和用户操作触发，离屏/后台暂停。减少动态效果时提供有意义的静态结果及必要的手动操作。

## 导出和验证按交付目标决定

- 只输出用户要求或任务明确需要的格式，不默认增加 MP4、多种 GIF、尺寸变体或发布操作。
- 视频/GIF 导出优先使用可设定时间的统一时间线，让网页状态与导出帧共享模型；不依赖录屏时的机器快慢决定动作与结果。
- 查看关键帧或一张覆盖开始、动作、结果、重置的联系图，重点找遮挡错误、图层越界、跳变、残影和数据不同步。
- 精确复刻任务才做必要的参考对照；不默认设置 PSNR 阈值、逐像素验收或对每一帧开展饱和检查。
- 导出后核实可播放性、实际时长、尺寸与需要的音轨。不要只用编码进程成功来宣告完成。

以上是对指定参考方案的条件化吸收，出处与未采纳规则见 [source-integration.md](source-integration.md)。
