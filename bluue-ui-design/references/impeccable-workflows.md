# 从 Impeccable 吸收的设计迭代方法

查阅与改写日期：2026-10-30。适用于方向选择、实质性重设计、精修和质量审查；局部修复只读取相关条目。本文由 Bluue 条件化改写，不是上游命令的执行入口，也不要求安装其引擎。

## 先判断当前区域服务什么目标

| 目标 | 主要判断 | 应保留的取舍 |
|---|---|---|
| 帮助决策 / Persuade | 用户能否理解价值、核实证据并选择下一步？ | 用产品本身的内容建立识别度，证据靠近主张；不默认巨型标题、数据墙或三列功能卡。 |
| 完成操作 / Operate | 用户能否快速、可靠地完成当前任务？ | 熟悉的控件、一致的状态、适当的信息密度。系统字体、表格和侧栏可以是正确选择，不为差异化增加学习成本。 |
| 阅读理解 / Read | 用户能否持续阅读、定位和理解内容？ | 文字节奏、行长、标题结构与必要导航；正文不被视觉表演打断。 |
| 体验作品 / Experience | 用户能否看清、探索和理解作品本身？ | 主体和媒介优先，操作退居辅助；有明确表达目的才采用更强表现。 |

按区域而不是行业贴标签。例如教师排课软件的介绍页帮助决策，课表编辑器服务操作，帮助文档服务阅读。一个页面可以混合目标，但每个主要区域应有清楚的主导任务。

## 把“优化一下”转成具体动作

根据用户反馈与实际问题选择动作，可以组合，不要求依次执行所有动作，也不为它们注册新的斜杠命令。

| 动作 | 改什么 | 不能变成什么 |
|---|---|---|
| 减法 / Distill | 去掉重复内容、无效装饰、多余变体和绕路操作。 | 隐藏高频功能、删去必要标签、单位、风险和错误信息。 |
| 强化 / Bolder | 让真正重要的内容在位置、比例、字重或对比上更明确。 | 全部放大、增加饱和度、巨型 Hero 或装饰动画。 |
| 收敛 / Quieter | 降低次要内容、背景、边框和动效的竞争。 | 降低正文与必要控件的可读性，抹平主次。 |
| 澄清 / Clarify | 操作用准确动词，状态说明事实，错误给出可执行恢复路径。 | 增加成段说明、口号、自造词，替产品编造能力。 |
| 适配 / Adapt | 按屏幕、输入方式和内容长度重排任务与空间关系。 | 把桌面等比缩小，裁掉溢出，默默删除功能。 |
| 补全 / Harden | 补足本次流程真实会遇到的边界与恢复路径。 | 为原型预设完整后台或对所有设备、语言和状态进行穷举。 |
| 精修 / Polish | 校准已有方向下的对齐、视觉重量、组件一致性与过渡。 | 偷换设计方向，靠新增装饰证明做了修改。 |
| 重设计 / Redesign | 保留事实、功能和约束，重新组织构图、信息层级与视觉语言。 | 只改颜色、字体、阴影和圆角。 |

用户明确要求重设计时，检查旧方向是否仍成立；不将“保持一致”误解为必须保留已被否定的结构。方向可合理推断就直接实施，只有影响结果且无法推断的关键缺失才询问。

## 视觉判断与技术证据分开

先按真实任务判断层级、阅读顺序、产品身份和操作可发现性，再核对可测量的实现问题，避免被扫描器的告警数量左右设计判断。

- **视觉判断**：问题出现在哪里、谁会因此看错或找不到、关系应该怎样调整。用实际界面与任务解释，不以“高级”“缺少惊喜”作为缺陷证据。
- **技术证据**：焦点、语义、对比度、溢出、状态同步、控件行为、性能等实际检查结果。区分源码推断、浏览器操作、模拟触控与真实设备，不把截图等同于交互验证。
- **交叉核实**：规则命中先核实用途与上下文；合理的例外不能机械删除。扫描无告警、编译成功和主观总分都不证明体验完成。
- **优先级**：任务阻塞、数据丢失、误导状态和不可访问路径优先；其次是流程与信息层级，再处理视觉一致性、动效和清理。不要把所有问题都列为严重，也不要用琐碎清单淹没主要问题。
- **可执行结论**：每个主要问题写清“位置、证据、用户影响、修复方向”。只列实际发现的问题，少量高价值结论即可；不强制打分、分配多个 Agent 或生成审查仪表盘。

审查请求先交付发现；优化与实现请求直接完成已授权修复。本次检查通过后结束，仅在改动、失败或新证据出现时追加验证。

## 从根因修复，而不是逐处覆盖

出现重复不一致时，先归因：缺少公共 Token、绕开既有组件、流程概念不一致，还是单个局部实现错误。分别在 Token、组件、流程或局部实现层修复，不对每个实例增加特例。

没有 DESIGN.md 不代表没有设计系统；先看现有界面、资产、组件和相邻流程。一次性差异不必抽象成系统。只有项目需要持续维护这些约定时才补充文档，不强制新建 PRODUCT.md、DESIGN.md 或上下文数据库。

## 状态设计必须说真话

- 区分加载中、首次无数据、筛选无结果、请求失败和权限不足，提供各自适用的下一步；失败不能伪装成空列表。
- 提交失败保留输入，成功反馈来自实际结果；按真实业务处理重复提交、过期请求和状态回退。
- 根据本次数据选择长文本、缺失值或窄屏等代表性边界。图标禁用 Unicode 替代不等于禁止用户输入 Unicode 文字或 Emoji。
- 自定义拖动、滑动或画布需要处理取消、失去捕获和失焦，确保中断后能继续操作；普通页面不因此增加手势测试。
- 浮层需要检查滚动容器裁切与焦点关系。优先使用合适的原生或已有浮层能力，不靠无限提高 z-index 掩盖布局问题。
- 仅实现相关状态：不是所有组件都需要加载、错误和成功态，也不是所有加载都需要骨架屏。

## 克制不等于统一成另一种模板

识别度来自产品特有的内容、任务组织和恰当的比例关系，不来自把所有项目换成同一套米白底、绿色按钮、圆角卡片或特殊字体。应用界面优先熟悉与可靠；表达型页面也应让主体承担表达。

沿用 Bluue 的字体、图标、字号、文案、圆角与动效边界。上游强制方向抽签、多候选评审、评分、双 Agent、检测器与 hooks 均不在本次融合范围；不继承“系统字体不可用”“嵌套卡片永远错误”等绝对规则。相关模式是否合适由任务与证据决定。
