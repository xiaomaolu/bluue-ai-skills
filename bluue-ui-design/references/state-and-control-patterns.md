# 状态、控件与连续过渡

用于新建或改造具体组件与流程。先记下「用户在做什么、系统实际处于什么状态、应该看到什么、下一步能做什么」，再复用现有组件。审查时用当前问题和改后示例解释判断，改动范围由任务决定。

## 空态先区分原因

| 原因 | 显示与下一步 |
|---|---|
| 首次使用或从未创建 | 说明缺少的对象，必要时给创建、导入或查看示例的入口。 |
| 搜索或筛选无结果 | 保留原搜索词和筛选条件，提供修改或清除入口。区分“当前条件无结果”和“还没有数据”。 |
| 任务已完成或队列已清空 | 用明确的完成状态收尾，例如「没有待审批项」。有自然的下一步再提供操作。 |
| 加载失败或离线 | 说明哪个内容没加载、当前数据是否仍可用，给可执行的重试或恢复。保留可用旧内容并标明状态。只有确有依据时才承诺输入或数据已保留。 |
| 权限不足 | 说明缺少的权限和真实可用的申请、切换或返回路径。申请后可就地显示已提交，并说明下一步。 |

按空间和任务选择外观。首次使用的整页可用简化线框说明内容将出现在哪里，前提是能提供信息且不会像仍在加载。对象明确的卡片可用现有图标或纯文字。侧栏、表格行和菜单通常一行状态加一个必要动作就够。完整状态可以有图示、标题、说明和行动，按需取舍。先写清实际情况，再补充原因、恢复或后果。面向用户翻译技术错误，诊断编号可放在支持详情。区块内保留一个清晰的恢复动作，整页用合适的主次按钮，小范围优先轻量操作。动态的无结果和失败应能被辅助技术感知，保留正在使用的输入和焦点。

## 等待反馈按可知程度选

| 场景 | 选择 |
|---|---|
| 点击后很快得到结果 | 立刻给按下或已受理反馈，结果就绪后直接显示。延迟独立加载指示可以避免闪烁；约 300ms 只作观察起点，结合任务风险、真实延迟和项目规范。 |
| 操作局部、进度未知 | 在按钮或受影响区域显示处理状态，保持尺寸和上下文；完成后就地反馈。短操作的可选通知适合补充结果，关键失败需要稳定的恢复入口。 |
| 首次加载、结构已知 | 骨架跟随真实布局。刷新已有内容时优先保留可用旧内容，并标识正在更新。失败时结束等待并给恢复路径。 |
| 耗时长且可测量 | 用真实百分比或已处理数量。进度不可测时显示确知的阶段或不定进度；支持取消或后台运行时给真实入口。 |
| 成功率高、可安全撤回 | 可乐观更新，同步列表、详情与计数，明确待确认状态。失败按本次变更回滚，保留输入并提供重试，防止旧响应覆盖后续操作。支付、永久删除、对外发送等以真实确认结果为准。 |

提交后的处理、成功和失败都应对应实际状态。用更长等待和失败各验一个相关情境，确认焦点、状态提示与恢复入口可用。相关的通知撤销和短加载细节见 [interaction-details.md](interaction-details.md)。

## 控件根据含义和生效时机选

| 用户意图 | 控件与边界 |
|---|---|
| 开关某个即时生效的设置 | Switch，稳定的标签显示它控制什么；保存失败恢复原状态。 |
| 在表单中勾选可选项，或同时选择多项 | Checkbox，是否随提交生效由流程决定。即时过滤也可以用 Checkbox，此时结果应立即更新。 |
| 选择一个值，且选项值得同时阅读 | Radio；确实允许弃选时提供「不确定」「无」或清除方式。 |
| 在少量短且稳定的互斥选项之间切换 | Segmented control；2–5 项只是起点。以本地化标签、可读性和实际空间判断。切换独立内容面板时用 Tabs 语义。 |
| 选项多、标签长或数据动态变化 | Select 显示当前值；确实难找时用可搜索的 Combobox，并设计无匹配与键盘选择。 |
| 从列表执行动作 | Menu 把命令交给对应处理流程，触发器保留原名称。危险操作仍遵循产品既有确认或撤销规则。 |

核对控件标签、当前值、键盘与触控、取消和保存行为。调整组件时保留已存数据；涉及从即时生效改为提交生效时，单独交代这个行为变化。

## 连续过渡与组件细节

- 列表进详情、卡片展开、搜索进入结果或 Tab 切换时，先找前后都存在且指向同一对象的标题、封面、搜索框或选中指示。使用稳定标识对应；有价值时只过渡共享元素。新内容及时可读，返回时尽量恢复位置和焦点。快速切换以最新状态为准，减少动态效果时保留清晰状态与相同操作路径。
- 重复组件优先复用语义 Token 和变体。没有间距体系时，4px 可以作为起点；先看项目现有尺度、内容密度、触控面积与光学校正。等距内嵌的圆角可以按外角减去有效内缩算起；药丸、圆形及不等距轮廓单独判断。连续圆角是局部视觉选项，保留基础圆角并核实目标平台效果。
- 精简文案时优先删重复解释。Tooltip 可放补充说明，并让键盘用户可访问。权限、风险、费用和完成任务所需的条件应留在操作附近；Alert 用于需要直接感知的问题或状态。
