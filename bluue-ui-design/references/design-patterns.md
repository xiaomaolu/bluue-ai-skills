# 从成熟设计系统学习取舍

用于新视觉方向、实质重设计，或用户要求学习成熟产品时。局部修复可沿用现有系统，不必每次联网调研。以下是方法参考，不是任何品牌的整体风格说明，也不授权复制其资产。

## 选择模式，而不是拼贴外观

1. 先按任务选参照：移动操作、复杂桌面工具、表单、内容阅读或产品展示。
2. 明确参照解决的问题，以及当前项目是否有同样的问题。
3. 提取行为、信息组织或系统规则，再映射到项目已有组件、Tokens 和品牌。
4. 写一句取舍理由。例如：沿用工具栏的共同左边界；把低频配置收进菜单，同时保持当前状态和错误可见。
5. 资料缺失或来源不确定时，说明这是自己的设计判断，不假称官方规范。需要精确数值或特定平台行为时核实对应官方章节。

## 官方原则可提供哪些判断

| 来源 | 经查阅的原则重点 | 在本 Skill 中的应用 |
|---|---|---|
| [Apple HIG — Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles) | 以人的目标为起点，保留用户掌控，利用熟悉模式，适应不同情境，简化不必要复杂性。 | 主行动与反馈清楚；状态变化保留上下文；优先熟悉的控件和可恢复路径。不能由此推导“所有界面都应玻璃化”。 |
| [Microsoft Fluent 2 — Design principles](https://fluent2.microsoft.design/design-principles) | 适应平台与熟悉行为、专注、包容性，以及有节制的品牌识别。 | 复用成熟基础组件，减少视觉噪音，让跨屏幕的任务连续；品牌差异放在确有价值的部分。文档示例比例不是本项目必须达到的复用指标。 |
| [Material 3 — Motion system](https://m3.material.io/styles/motion/overview/how-it-works) | M3 Expressive 的动效系统采用物理/弹簧模型，关注连续的运动关系。 | 可以借鉴受控、可中断的状态连续性；不把明显弹性或某种 spring 参数强加给当前网页，平台适配和项目约定优先。 |
| [IEEE PCS — Elements of Visual Communication](https://procomm.ieee.org/elements-of-visual-communication/) | 对比、重复、亲密性与对齐用于传达元素之间的关系。 | 用这四条原则检查信息关系，不能把它们变成自动打分或固定布局公式。 |

查阅日期：2026-10-26。外部文档会更新；上述为当次内容的概括，具体平台实现以当前官方文档与实际组件为准。

## 克制不是弱化

- 减少竞争的强调，而不是把文字、分隔和状态都调淡。
- 复用系统结构，而不是给每个区块重新发明组件。
- 用共同边缘、留白和字体角色组织阅读，而不是给每组内容都套边框。
- 用短而连贯的变化解释状态，而不是让所有东西漂浮、闪烁或进场。
- 允许品牌特色承担重点，不必在每个组件上重复表演品牌。
- 只借鉴与任务相近的模式。消费级展示页的大标题、大留白和慢节奏，不天然适合数据工作台。
