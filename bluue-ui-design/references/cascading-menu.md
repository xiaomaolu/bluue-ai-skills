# 级联菜单：保护指针路径，保持明确操作及时

只在悬停展开的多级菜单存在误切换问题时应用。来源是用户于 2026-10-27 提供的《999 个小技巧，让你 Vibe 的产品更有质感》002 粘贴文本，并结合当日查阅的官方文档进行取舍。原文未提供可核实的作者、发布日期或文章链接，不称为新发明或已验证的最佳参数。

## 优先复用

先检查现有 Menu/Submenu 的 hover intent、pointer grace、安全走廊或类似能力，保留其 API、焦点、键盘与无障碍模型。若项目已使用 Floating UI，可评估 [useHover 的 safePolygon](https://floating-ui.com/docs/usehover#safepolygon)。其安全多边形支持从触发器移向浮层而不关闭；它本身不等于完整的兄弟菜单切换协调器，需要与菜单树逻辑配合。不要在现有保护上重复叠加计时器，也不为这个效果单独引入第二套菜单系统。

## 应吸收的行为

- **保护斜向路径**：已有子菜单打开时，指针朝它移动的路径可获得短暂保护，沿途其他行不立即抢走高亮或切换子菜单。进入目标子菜单、明显离开路径或明确点击其他项后，结束相应保护。
- **保护有上限**：几何命中只代表可能的意图，不能无限锁住旧菜单。指针停在另一个菜单项上后，应在有界时间内切换；同一候选项的 pointermove 不反复重置截止时间。
- **分别管理打开、切换、关闭**：悬停短暂掠过不必展开；离开整棵菜单的有效交互区域后可短暂宽限，返回即取消关闭。进入另一分支后撤销旧分支的待执行任务，避免已关闭菜单被旧定时器重新打开。
- **高亮与状态同步**：处于保护路径内的行不因 CSS `:hover` 闪亮。由组件实际活动状态驱动菜单行样式；同时保留独立清楚的键盘焦点，不能全局禁用 hover 或吞掉明确点击。
- **明确操作优先**：点击、触控点击及键盘操作不等待悬停延时；点击外部按既有 dismiss 逻辑关闭。指针离开不能关闭仍由键盘焦点操作的子菜单。

## 几何与实现边界

- 自定义时，使用同一坐标系下的指针历史与子菜单实际矩形；可以从离开父行的位置及子菜单近侧边界建立三角形/走廊。不要用当前指针作为三角顶点再测试当前指针，造成无意义的恒命中；连续历史采样也应处理重复点、退化三角形和方向变化。
- 依据最终布局处理左右翻转、视口移位、滚动、缩放、嵌套层级和 Portal。浮层边界变化后更新几何；必要时增加少量容错缓冲，但不能覆盖大片相邻行。视觉重叠不是跨越间隙的唯一办法。
- 不把不可见安全区实现为阻挡其他控件点击的大透明遮罩。菜单卸载、关闭或输入方式切换时清理对应计时器和监听。
- 延时采用组件默认值或项目命名 Tokens。原文打开 220ms、关闭 360ms、保护上限 1200ms 仅是可试验的示例；较长保护也可能使切换显得迟钝。80ms 轮询、边缘宽度公式均非必须，优先事件驱动并配合有界截止计时。
- 拖拽悬停展开仅在产品本来支持拖放时考虑，按实际拖拽事件与目标有效性处理；不因原文有 420ms 示例就新增拖拽能力。

## 键盘、语义和视觉

遵循现有组件与 [WAI-ARIA Menu and Menubar Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/)：打开子菜单后安排焦点，关闭后回到对应触发行；Escape 通常先关闭当前菜单并返回其触发处，不能把原文“总是一次关闭全部”写成所有菜单的规则。按平台/方向约定处理方向键，保留 Tab 离开路径及适用的 `aria-haspopup`、`aria-expanded`。普通网站链接导航不因视觉上分层就强行套 `menu/menuitem` 角色。

尺寸、行高、标题、模糊、圆角、主题和动效沿用产品系统。原文要求的过冲曲线、图标变形、暗色品牌图标反相及长主题过渡不自动采用；品牌图标用合适资产，减少动态偏好仍可立即理解与操作。只有用户要求复刻该效果时，才针对这些视觉细节适配。

## 对应风险的验证

实际修改菜单时，检查：斜向穿过兄弟行能进入目标子菜单；停在新行能及时切换；短暂移出再返回不消失；快速反复操作没有旧计时器回弹。发生翻转/滚动或多级嵌套时再覆盖对应路径，并检查键盘进退、外部关闭与触控。只有自写几何算法时，为边界、退化及翻转情况补必要的纯函数测试；仅更新 Skill 文本不要求生成菜单或开展整站测试。
