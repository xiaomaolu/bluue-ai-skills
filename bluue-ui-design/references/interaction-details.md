# UI 细节技巧：滚动线索与连续操作

用于局部交互打磨，不是每个页面都要完成的效果清单。优先复用已有组件及其默认行为；只有发现实际缺口才补充。下列“本 Skill 的适配”是设计判断，不冒充来源的逐条规定。

## 1. 稳定高度列表：露出下一项

来源：用户明确提出的设计偏好。

- 适合命令面板、选项列表、局部滚动卡片带：内容确实超出容器、主要行高可预测时，初始视口可容纳若干完整项，再露出下一项足够可辨认的一部分。让下一项的轮廓提示滚动方向，不只剩一根难以理解的线。
- 先满足可用视口、阅读和触控需求，再调整露出量。没有通用的“半行”“固定像素”标准；分组标题、行间距、内边距也占高度。可变行高、文字放大、移动键盘出现时，不硬编码 N 倍行高。
- 不为制造线索而截断正在操作的项、错误信息或唯一的主操作；普通正文页也不刻意裁半行文字。无溢出时正常显示全部内容。
- 滚到底部应能完整查看最后一项及操作，不用虚假的底部占位或永久渐隐暗示仍有内容。横向列表同理，并尊重阅读方向。

## 2. 方向键导航：提前滚动，保留上下文

用户要求结合当前 [cmdk 官方 README 的 List 说明](https://github.com/dip/cmdk#list-cmdk-list)：文档支持通过 `scroll-padding` 在靠近视口边缘时更早将项滚入视野；这是仍在使用的实践，不宣称始于 2026 年。

- “到达边缘”指活动项接近滚动视口的有效边缘，不是走到数据最后一项。上下方向都适用；先让活动项完整可见，再尽量露出前/后一项的线索。
- 在真实滚动容器设置块方向 `scroll-padding`，结合组件现有的活动项滚动能力；CSS 本身不会监听方向键或启动滚动。不要重复接管成熟组件的键盘逻辑。
- 粘性分组标题、固定搜索框或底部操作条如果覆盖内容，要计入有效可视区域。每次只滚到必要位置，不让每行都跳到居中，也不让外层页面跟着移动。
- 快速连按时以最新活动项为准，不排队播放平滑滚动。鼠标停在列表上不应因键盘滚动造成的内容移动抢回选中；按真实输入来源处理指针与键盘切换。
- 行高不可预测或组件用自定义滚动时，依据实际元素边界计算余量；虚拟列表先用其滚动 API 挂载目标，再处理可见性及活动项引用，不能依赖不存在的 DOM。
- 保留组件既定的焦点模型；若输入框通过 `aria-activedescendant` 指向活动项，不为滚动而把 DOM 焦点搬离输入框。是否首尾循环沿用产品约定，不因留边技巧自动开启。

这里的“提前露出下一项”还取决于余量、间距和行高；仅设置一个很小的 `scroll-padding` 不保证一定看得到相邻项。按实际内容调整。

## 3. 滚动阴影随真实溢出出现

当前 [Base UI Scroll Area](https://base-ui.com/react/components/scroll-area) 提供方向性的溢出状态、距离变量和渐隐示例。

本 Skill 的适配：当半露出不适合可变行高时，可用轻微边缘阴影或明确滚动条作为替代。到达某一端，撤掉该端提示；内容或容器尺寸变化后重新判断。优先不遮文字的阴影，渐隐不得削弱活动项、焦点环和关键内容。不要同时叠加半露出、浓阴影、箭头和提示文案。

## 4. 异步搜索：高亮始终对应真实结果

[Base UI 1.9.0（2026-10-09）](https://base-ui.com/react/overview/releases/v1-9-0) 修复了异步结果自动高亮，并补充高亮变化的原始事件信息。

本 Skill 的适配：按查询版本丢弃过期响应；结果更新时用稳定 ID 对齐活动项，不按旧索引误选另一条。原项消失后采用明确的重置策略；空结果、仍在更新时的 Enter 不能触发旧命令。中文输入法组词期间的 Enter 用于确认输入，不执行高亮命令。

## 5. 通知：用户正在交互时不要消失

[Base UI 1.9.0（2026-10-09）](https://base-ui.com/react/overview/releases/v1-9-0) 修复了多种交互重叠时通知计时仍应保持暂停的问题。

本 Skill 的适配：带撤销或重试的通知，在悬停、键盘焦点等暂停条件任一仍成立时保持可用；不能鼠标移开就忽略仍留在通知里的焦点。关键失败与恢复入口另有持久位置，不能完全依赖会超时的通知。

## 6. 移动抽屉：键盘和滚动各司其职

[Base UI 1.9.0（2026-10-09）](https://base-ui.com/react/overview/releases/v1-9-0) 修复了虚拟键盘多余空白、焦点滚动及部分拖动/滚动冲突。

本 Skill 的适配：键盘出现后仍能看到当前输入与必要操作，避免浏览器已经腾出空间、业务层又重复补偿一次。内容滚动不能轻易误触关闭抽屉；优先用组件已有的手势仲裁和排除区域。按当前可用视口约束高度，不把桌面固定高度照搬到手机。

## 7–9. 提示、加载与局部滚动的克制处理

以下三条参考 [Vercel Web Interface Guidelines](https://vercel.com/design/guidelines) 当前版本，具体取舍是本 Skill 的适配：

| 场景 | 采用的技巧 | 边界 |
|---|---|---|
| 扫描一排工具栏图标 | 首个 Tooltip 稍作等待；同组连续浏览时更快出现，离开一段时间后恢复。 | 用组件的分组计时，不让每个按钮各自闪烁。必要说明直接可见；键盘也能获取补充信息。 |
| 点击后请求很快结束 | 立即反馈按下/处理中，适度延迟重型 loading 视觉，避免闪一下骨架；按钮保留原标签和稳定尺寸。 | 完成即显示真实结果，不为了播满动效阻塞操作；不固定套用延时数字，也不假设框架自动覆盖所有请求状态。 |
| 弹窗列表已经滚到底 | 按需约束局部滚动传播，避免继续滚动把背后页面带走。 | 约束放在对应滚动容器，不全站禁用原生滚动、缩放或导航手势；仍可键盘退出和关闭。 |

## 选择与轻量验收

- 先选本次能改善发现性、连续性或容错的条目；同一个问题通常一种明确线索即可。
- 若实际改了列表，检查有溢出与无溢出、两端边界、快速方向键和过滤后活动项；存在分组、虚拟化或移动键盘时再补相应情境。不要求所有 UI 任务跑这张表。
- 本次只是更新 Skill 文本时，检查引用和规则一致性即可；不能把文字校验说成已验证组件行为。
