# 视觉精修：让局部关系共同服务信息

适用于截图前后对比、功能卡片和已有页面的精修。保留有效结构，优先修正主体辨识、视觉重量、文字组织与语义关系；不把精修等同于调边距或增加材质。

## 判断顺序

1. **意义正确**：标题承诺什么，图中对象与状态是否支持它？
2. **主体清楚**：正常展示尺寸下能否辨认重点对象？是否被裁切、装饰或过暗处理淹没？
3. **重量平衡**：比较相邻区域实际可见的明暗面积、轮廓、密度和重心，而非只比较图片盒子的宽高。
4. **阅读顺畅**：公共对齐线、文字宽度、换行、图文间距是否共同支持扫描顺序？
5. **细节一致**：最后再处理边框、图标、颜色与局部光学校正。不要先用特效掩盖前四项的问题。

## 本案例不能照单全收的部分

- 左下标题是“工作结束后移除权限”，修改版却显示多项 `Access`；原版至少可见部分 `Removed`。如果修改版是“移除前”的状态，需要明确交代或通过真实状态变化说明，不能只因更亮更整齐就视为更准确。
- 右下标题承诺最终付款后归用户，但可见资产标签仍有 `Owner: DesignMe`，另一项是 `Owner: you`。这让对象更具体，却没有清楚完成全部归属转移的叙事；应按实际业务修正或标明转移前后，不能擅自虚构完成状态。
- `3 open` 与 `5 open` 等内容差异属于状态/数据变化，不是纯视觉调整。精修时不为构图美观改动业务事实。
- 截图中的微小字和深色内容是否能在真实屏幕上读清，需要结合实际尺寸和颜色验证；不能因为整体更协调就宣称无障碍已达标。

## 实施方式与范围

- 比较时写“位置 → 可观察差异 → 对阅读或理解的影响 → 可复用规则”，避免只说更高级、更舒服或更有质感。
- 在功能卡片里分别规划文案区和图形区；同角色标题/说明维持公共起点，图形按视觉重心安排。不要强迫所有卡片图形同尺寸、同亮度或同一构图。
- 重要对象通常应保留可辨识轮廓与周围空间；确需出框或裁切时，保留含义。用于提示滚动的部分露出遵循交互细节规则，不据此随意裁切核心插图。
- 黑底可用适度表面差异、边缘或局部明暗建立层次；避免无区别地加重描边、阴影和光晕。可读性与真实状态优先于风格统一。
- 先修对理解影响最大的区域，再处理小尺寸、间距和笔画。精修完成后按正常展示尺寸查看整体和受影响区域；没有复刻要求时不强制像素级对比或整站测试。
- 从单次参考中学习判断方法，不将其配色、金属锁、卡片数量和布局写成所有项目的默认模板。
