## 从 landing-page-design 吸收

| 处理 | 方法与理由 |
|---|---|
| 吸收 | 先考虑受众、任务、内容与证据，再确定结构和样式。主张附近提供可核实证据，CTA 说明实际动作和结果。 |
| 吸收 | 一致的字体/间距/圆角体系、真实内容长度与状态、按区块做可评审的改动。已有系统优先，光学校正不被刻度机械禁止。 |
| 条件化 | 一项主要转化目标适用于特定落地页；产品工作台可以有多个独立任务区域，不能套同一个转化漏斗。 |
| 条件化 | 文案、利益点、FAQ 和风险说明由真实内容决定；缺少证据不能虚构客户评价、免费试用、退款、取消政策或收益数字。 |
| 未采纳 | 对任意网页任务都触发并覆盖框架/设计系统的宽泛范围。局部修复保持范围。 |
| 未采纳 | 固定首屏构成、强制标语揭示区块、固定 CTA 措辞和区块数量；强制居中首屏、玻璃导航或渐变标题。它们不符合所有产品。 |
| 未采纳 | 禁止特定常用字体/图标、只能用某组字体、字号只能向下取整、固定按钮尺寸和统一时长等全局规则。它们可能破坏已有品牌、中文排版、触控和可读性。 |
| 未采纳 | “背景绝不能渐变”“所有卡片必须完整描边”等风格绝对化要求。根据功能和系统决定。 |
| 未采纳 | 自动修改 SEO 索引策略、自动增加保障或承诺。此类变更需要实际需求和事实依据。 |

## 从 design-to-motion 吸收

| 处理 | 方法与理由 |
|---|---|
| 吸收 | 区分独立展示与网站嵌入；动画不等于重设计，明确输入画面和背景的保留范围。 |
| 吸收 | 先写动作故事，保持图层、裁切与对象关系，信息变化来自共享状态；导出使用可控时间线。 |
| 吸收 | 查看关键过程、结果和循环衔接，检查越界、残影、跳变和状态同步；交付核实实际文件。 |
| 条件化 | 从空态载入、循环、图层导出、较慢节奏和特定尺寸适用于部分展示任务，不能强加给产品 UI。 |
| 未采纳 | 每个视觉区域持续循环、每隔一两秒必须有动作、统一升起和模糊、默认脉冲/扫光/浮动。它们可能引入噪音和负担。 |
| 未采纳 | 一律导出 MP4 和多套 GIF；默认规定帧率、文件尺寸或必须精确到像素。不超出用户交付范围。 |
| 未采纳 | 每次都进行 PSNR、全帧掩膜和重型逐帧比较。只在用户精确复刻要求或具体缺陷确实需要时使用相关验证。 |

## 与现有偏好的关系（合并后）
