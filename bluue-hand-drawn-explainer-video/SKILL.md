# 手绘线稿概念科普短视频

用于给用户（水印「蓝与蓝之间的ai差值」）制作一支讲解某个理论或概念的短视频。系列已做过：沉默的螺旋、框架理论、习得性无助、汉隆剃刀。

## 一、工作流程（顺序不能乱）

1. **先出计划，不要直接做。** 用户通常会说「先看看计划」。计划包含：钩子、分段脚本（旁白 + 画面）、结尾金句候选（2–3 个）、主色建议、需要核对的事实清单。等用户确认或修改后再动手。
2. **核对事实。** 每个数字、年份、实验设计、原话都用 WebSearch / WebFetch 核对；核对不到的就改写成更保守的说法，并在交付时说明。
3. **TTS → 时间轴 → 画面 → 抽帧检查 → 配乐 → 渲染 → 交付。**
4. **交付**：MP4、封面 PNG（第一帧截图）、网页版 Artifact（带音频的可播放页面），回复里说明结构、注意事项和来源链接。
5. 用户随后通常会要「文案」，按第七节格式给。

## 二、内容结构（约 2 分钟，9:16）

| 段落 | 内容 | 要点 |
|---|---|---|
| 0 钩子 | 「为什么……？」+ 一个**真实具体的案例** | 第一帧就是封面：手绘画框里的大字标题 + 钩子问题 + 一幅主图。用户明确要求钩子要深、要具体，像「同一块牛肉，为什么75%瘦肉更好吃」「全世界同时蓝屏，是谁在搞鬼」，不要用太日常太轻的例子（如「同事已读不回」被否过）。 |
| 1 概念 | 引出理论名和一句话定义 | 给出提出者和年份 |
| 2 证据 | 经典实验/研究，带具体数字 | 标注出处小字；示意性的图要标「示意」 |
| 3 生活里 | 2–3 个日常对照（「你以为 / 更可能」） | 代入感 |
| 4 反转/争议 | 理论被修正、被滥用、效应很弱等 | 用户很喜欢反转；每集必须有局限或争议段 |
| 5 怎么用（可选） | 两步法、自检问题 | |
| 6 结尾 | 一句有哲思的金句 + 一个互动问题 | 金句要对称、可截图传播 |

**真实事件**：尽量用真实事件，但**隐去公司名、平台名、刊物名**（写「一家网络安全公司」「某平台」），画面角落标「已隐去名称」。只讲有公开记录或判决的事实。

## 三、视觉风格

- 画布 1080×1920，背景 `#fbfaf7`，墨线 `#141414`，灰 `#9a9a96`。
- **只用一个主色**，每集换一个，与前几集区分：沉默的螺旋 `#ff5a36` 橙红；框架理论 同橙红；习得性无助 `#2f5bea` 钴蓝；汉隆剃刀 `#6c47ff` 紫。新一集选未用过的（如草绿、青、琥珀）。
- 参考风格：粗黑线、留白多、头发涂满黑块、四角小星星点缀的漫画线稿；人物全部原创，不画已知角色。
- 线条抖动：整组插画套 SVG 滤镜 `feTurbulence(baseFrequency 0.035, numOctaves 2) + feDisplacementMap(scale 3.2)`，每帧把 seed 设为 `1 + floor(t*8) % 4`，得到 8fps 的「线条呼吸」。
- 常用手绘元件：双线画框（标题框）、对话气泡（talk 橙线 / dots 省略号 / grey 灰线）、doodle 小人头（圆脸 + 黑发块 + 点眼）、主角女孩（波波头 + 主色发夹）与男生、手机、柱状图、仪表盘、天平、印章「反转」、剃刀/尺子等道具。
- 字体：全部 Noto Sans SC（粗体 700/900）；英文副标题字间距加大、灰色。
- 顶部固定页眉：左上理论名（900 粗）+ 英文名（灰色小字），右上水印「蓝与蓝之间的ai差值」。
- **安全区**：字幕在 y≈1450–1520；底部 25% 和右侧按钮区不放关键信息；出处小字放在 y≤1380。

## 四、动画引擎（单文件 HTML + SVG）

- 每个场景 `<g class="scene" data-s data-e>`；场景之间 0.7s 交叉淡入淡出。
- 元素用 `data-at`（相对场景开始的秒数）、`data-out`、`data-d` 控制；类型由 class 决定：`fade` / `slide`(data-from="x,y") / `scale`(data-c, data-sx0, data-sy0) / `pop` / `draw`(pathLength=1 描线)。
- 自定义动画用 `data-anim`（如 shrink、scroll、typedel 打字又删、needle 仪表指针、tilt 天平、fill 进度条、hand 时钟）。
- 暴露 `window.__seek(t)` 供逐帧截图；URL 带 `#render` 时隐藏播放器 UI。
- **时间轴由 TTS 时长驱动**：每句旁白有 id 和所属场景；场景开始 = 上一场景结束；句首 = 前一句结束 + 间隔(0.4–0.5s)；每场景加 LEAD(0.6s) 和 TAIL(1s，最后一场 4s)。画面元素时间用 `rel(id, scene, fraction)` 表示「某句话读到百分之几时出现」。
- 字幕：每句一条，单行 ≤18 字，超长在标点处拆两行，字号 `min(50, 930/最长行字数)`；`【】` 标记的词用主色高亮。

## 五、旁白（TTS）

- sherpa-onnx + Kokoro multi-lang v1.1，`sid=3`（zf_001 女声），语速 1.05–1.12，古文/金句 0.98–1.0。
- 每句单独合成，裁掉首尾静音（阈值 0.01）。
- **朗读替换**：数字年份读成中文（「二零二四年」「百分之八十六」「八百五十万台」）；去掉引号和书名号；冒号换逗号；英文名一律改中文（Kokoro 会漏读夹在中文里的英文）；多音字用同音字替换（如「强饮」写「抢饮」）。
- 合成后可用 SenseVoice ASR 回听，检查是否漏句。

## 六、声音与渲染

- 配乐：88 BPM，C–Am–F–G，Karplus-Strong 拨弦八分音符琶音 + 低音 + 轻 kick（6 秒后进入）+ shaker；音乐整体 ×0.55，并按人声包络压低 50%（ducking）。
- 音效：元素出现 `data-sfx="pop"` 用短促上滑音；打字用 tick；换场用纸张 swish。
- 混音：`alimiter=0.95` + `loudnorm I=-15 TP=-1.5`，输出 mix.wav 和 mix.mp3。
- 渲染：本地 http.server 提供 render.html（Google Fonts 换成本地字体），Playwright 1080×1920 截 JPEG(q93) 管道进 ffmpeg libx264 crf17 30fps；按帧区间分 4 个进程并行，各写一个 mp4，再用 concat demuxer `-c copy` 拼接，最后 `-c:v copy` 合入音频（AAC 192k，`+faststart`）。
- 正式渲染前，在内容最满的时刻抽 8–10 帧拼成联系表检查：文字溢出、元素重叠、字幕与出处小字冲突、该出现/消失的元素是否正确。
- 网页版：同一 HTML 把 mix.mp3 以 base64 嵌入 `<audio id="narr">`，用 Artifact 发布（icon: play）。

## 七、发布文案格式（用户每集都会要）

1. **标题**：5 个候选，注明第 1 个最适合当封面大字。
2. **正文**：按视频结构的短句分行版，结尾是金句 + 👇 互动问题。
3. **简短版**：一两行。
4. **话题标签**：8–10 个，最后固定 `#蓝与蓝之间的ai差值`。
5. **发布小建议**：标题怎么选、置顶评论一句、合集归类；涉及心理健康时提醒温和引导求助。

## 八、注意

- 计划阶段就把「需要核对的事实」列给用户。
- 交付回复里明确写出：哪些图是示意、哪些数字是估计、哪些说法做了保守处理。
- 不画真实人物肖像和已知角色；涉及争议人物只讲判决或公开记录。
- 用户偏好：画面干净、少颜色少描边；节奏要快；每集都要有「反转」或「局限」。
