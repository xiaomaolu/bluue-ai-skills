# Content Architecture

Use this reference when turning long or structurally complex source material into one infographic or a series.

## Objective

Compress meaning without flattening it. Convert paragraphs into a visual hierarchy that preserves the source's central claim, critical evidence, causal structure, comparisons, sequence, and implications.

## Long-form decomposition

Build an internal outline with four levels:

```text
L1 — Series thesis
L2 — 3–7 frame messages
L3 — 2–4 supporting facts or relationships per frame
L4 — exact numbers, labels, dates, names, and citations
```

Do not move every L4 item onto the canvas. L4 is a source-control layer used to protect accuracy.

## Frame planning

Each frame should answer one question:

- What changed?
- Why does it matter?
- How does it work?
- What does the data show?
- What are the differences?
- What are the risks or boundaries?
- What should happen next?

If one frame answers several unrelated questions, split it.

## Common narrative patterns

### Research / report

```text
1. Core thesis / cover
2. Context or problem
3. Main mechanism or structural shift
4. Key evidence / comparison
5. Risk, limitation, or regulatory boundary
6. Action or outlook
```

### Data story

```text
1. Hero result
2. Breakdown
3. Trend
4. Comparison / benchmark
5. Implication
```

### Explainer

```text
1. What it is
2. Key parts
3. How it works
4. Example
5. Why it matters
```

### Process

```text
1. Goal / starting point
2. Steps 1–2
3. Steps 3–4
4. Decision or exception
5. Outcome / checklist
```

Do not force these patterns when another sequence tells the story better.

## Compression rules

Keep:

- thesis statements
- decisive numbers
- structural relationships
- before / after differences
- named stages
- critical caveats
- representative examples
- final implication

Cut or demote:

- repeated setup
- rhetorical transitions
- multiple examples proving the same point
- background that is obvious once the visual is seen
- sentences whose only purpose is prose flow

## Visual mapping

Map semantic structure to a visual form deliberately:

| Semantic shape | Preferred visual form |
|---|---|
| trend | line, area, slope, sequence |
| comparison | paired columns, matrix, bars, split screen |
| hierarchy | tree, nested blocks, levels |
| process | directional path, numbered stages, swimlane-lite |
| cause and effect | chain, funnel, branching path |
| ecosystem | network, clusters, orbit, map |
| allocation | stacked bar, blocks, treemap, donut only when simple |
| key takeaways | editorial hierarchy, hero number, 2–4 support modules |
| boundaries | allowed / restricted split, threshold line, guardrail strip |

## Series diversity without style drift

Avoid using the same card grid on every frame. Within one style lock, vary the dominant composition:

- frame 1: hero typography + one visual anchor
- frame 2: directional flow
- frame 3: data chart
- frame 4: network or comparison
- frame 5: editorial split

Consistency comes from palette, type character, line language, image treatment, spacing rhythm, and recurring motifs, not from repeating one layout.
